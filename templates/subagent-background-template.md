## 🔬 审计流程与思路

### Phase 0: 开放式探索 (15 分钟)

**目标**: 在模式匹配之前，先理解业务逻辑，用对手思维发现非显而易见的攻击面。

**业务逻辑漫游**:
1. 这个模块的核心业务价值是什么？
2. 有哪些"不应该发生"的状态？（负数金额、越权访问、跳过步骤）
3. 哪些操作是高价值目标？（支付、权限变更、数据导出、管理操作）
4. 模块间的信任边界在哪里？内部 API 是否假设调用方可信？
5. 状态机是否可以被打乱？（先调用 B 再调用 A，跳过 C）

**对手思维检查**:
```
[ ] 我能以非预期顺序调用这些操作吗？
[ ] 我能以其他用户的身份执行操作吗？（IDOR、越权）
[ ] 我能让服务器替我发请求吗？（SSRF）
[ ] 我能让两个操作同时发生产生竞态吗？（TOCTOU）
[ ] 我能通过链式利用把中危变成高危吗？
[ ] 硬编码的密钥/令牌/凭据在哪里？
[ ] 错误消息会泄露什么内部信息？
[ ] 加密/签名实现是否有缺陷？（弱算法、密钥复用、可预测随机数）
```

### Phase 1: 代码地图绘制 (10 分钟)

**目标**: 快速了解模块结构和关键函数

**步骤**:
1. 列出所有源文件及其行数
2. 识别入口点 (public 方法、REST 端点、事件处理器)
3. 识别危险 Sink (SQL 执行、文件操作、命令执行、网络请求)
4. 绘制简化的调用关系图

**示例**:
```
入口点                    Sink
┌─────────────┐          ┌──────────────┐
│ REST API    │ ───────→ │ Query.execute│
│ /api/query  │          │              │
└─────────────┘          └──────────────┘
     ↓                         ↓
┌─────────────┐          ┌──────────────┐
│ Service     │ ───────→ │ FileInputStream│
│ .process()  │          │              │
└─────────────┘          └──────────────┘
```

### Phase 2: 数据流追踪 (25-35 分钟)

**目标**: 追踪用户输入从 Source 到 Sink 的完整路径

#### 2.1 识别 Source (用户输入入口)

**常见 Source**:
```java
// HTTP 请求参数
@RequestParam("xxx") String userInput
@PathVariable("xxx") String pathParam
@RequestBody JsonNode requestBody

// 文件读取
FileInputStream.read()
BufferedReader.readLine()

// 网络接收
Socket.getInputStream()
HttpURLConnection.getInputStream()
```

**在本模块中的 Source**:
```
文件：XXX.java:行号
方法：public void process(@RequestParam("query") String query)
输入类型：HTTP 查询参数
可信度：❌ 不可信 (外部用户可控)
```

#### 2.2 识别 Sink (危险操作)

**常见 Sink**:
```java
// SQL/JCR 查询
queryManager.createQuery(userInput, Query.SQL)
statement.executeQuery("SELECT * WHERE name='" + userInput + "'")

// 文件操作
new FileInputStream(userPath)
Files.readAllBytes(Paths.get(userPath))

// 命令执行
Runtime.getRuntime().exec(userCommand)
ProcessBuilder.start()

// 反序列化
ObjectInputStream.readObject()
JSON.parseObject(userInput, TargetClass.class)
```

**在本模块中的 Sink**:
```
文件：XXX.java:行号
方法：session.getItem(path)
危险类型：JCR 路径访问
风险：路径遍历
```

#### 2.3 追踪完整调用链

**追踪方法**:
1. 从 Source 方法开始，逐层向下追踪
2. 记录每层函数的文件名和行号
3. 标注每层的处理逻辑 (验证、过滤、转换)
4. 到达 Sink 时完成调用链

**调用链模板**:
```
[Source] userInput (XXX.java:10)
  ↓ 
[Process] validateInput() (XXX.java:25)
  │ 处理：检查 null，但未验证内容
  │ 风险：仅检查 null，未检查恶意内容
  ↓
[Process] buildQuery() (XXX.java:40)
  │ 处理：字符串拼接
  │ 风险：❌ 直接拼接，无 parameterization
  ↓
[Sink] queryManager.createQuery() (XXX.java:55)
  ↓
执行恶意查询 → CVE
```

### Phase 3: 安全控制分析 (10 分钟)

**目标**: 识别现有安全控制措施并评估绕过可能性

#### 3.1 全局策略限制

**检查项**:
```
[ ] 是否有输入验证框架？(如 Hibernate Validator)
[ ] 是否有统一的安全过滤器？(如 Spring Security)
[ ] 是否有访问控制列表 (ACL) 检查？
[ ] 是否有路径规范化函数？
[ ] 是否有白名单验证机制？
```

**在本模块中的全局策略**:
```
策略名称：WCMCoreUtils.getUserSessionProvider()
作用：获取当前用户会话
限制：理论上应受 ACL 限制
绕过可能：⚠️ 使用 getSystemSessionProvider() 可绕过
```

#### 3.2 局部验证逻辑

**检查每个 Source → Sink 路径上的验证**:
```
验证类型          是否存在    有效性    绕过方法
─────────────────────────────────────────────────
null 检查         ✅ 是       ❌ 不足    发送非 null 恶意值
长度限制          ❌ 否       -          -
白名单验证        ❌ 否       -          -
路径规范化        ❌ 否       -          -
权限检查          ⚠️ 部分     ❌ 可绕过  使用系统会话
```

#### 3.3 绕过可能性分析

**常见绕过技巧**:
```
1. URL 编码绕过: %2e%2e%2f → ../
2. 大小写绕过: /etc/passwd → /Etc/PASSWD
3. Unicode 绕过: \u002e\u002e → ..
4. 双重编码: %252e%252e → %2e%2e → ..
5. 路径截断: file.txt%00.jpg → file.txt
6. 系统会话绕过: getSystemSessionProvider() → 超级用户权限
```

**本模块的绕过分析**:
```
安全控制：session.getItem(path) 依赖 JCR 权限
绕过方法：使用 getSystemSessionProvider() 替代 getUserSessionProvider()
影响：完全绕过 ACL，访问任意节点
可利用性：✅ 高 (代码中多处使用系统会话)
```

### Phase 4: CVE 发现与报告 (10-15 分钟)

**目标**: 确认可利用漏洞并生成 CVE 就绪报告

#### 4.1 CVE 判定标准

**必须满足所有条件**:
- [ ] 有明确用户输入入口 (Source)
- [ ] 有完整调用链 (Source → Sink)
- [ ] 无有效安全控制阻断
- [ ] 可编写可执行 POC
- [ ] CVSS ≥ 7.0

**过滤掉**:
- ❌ 理论漏洞 (无输入入口)
- ❌ 被安全控制完全阻断
- ❌ 需要不可能的条件
- ❌ CVSS < 7.0 (除非可串联)

#### 4.2 报告格式

**每个漏洞必须包含**:
```markdown
## CVE-2026-XXXX-XXX: [漏洞名称]

### CVE 就绪性
- 可利用：✅ 是
- POC 可行：✅ 是
- CVSS ≥ 7.0: ✅ 是 (评分：__)

### 位置
`文件：行号`

### 完整调用链
[Source] → [Process] → [Sink] → [Impact]

### 安全控制与绕过
现有控制：[描述]
绕过方法：[描述]

### 影响
[攻击者 achieves 什么]
```

- [ ] 分析绕过可能性
